# SDK Runner Decisions

This document records the owner decisions needed before implementing real SDK runners.
It is intentionally not an implementation contract yet; each item below must be resolved
before the `mock_fixture` runner is replaced or complemented by a live SDK runner.

## Current Decision State

- Tool side-effect policy is decided: framework tools stay read-only. Propose/write behavior must not write directly to candidate files; the runner collects tool results and emits candidate artifacts at the end of the run.
- Publication freeze is deferred until the remaining development work is complete.
- `extract` may auto-generate a source snapshot when `--source-manifest` is omitted.
- Real SDK runner implementation remains deferred until the decisions below are resolved.

## Decisions Needed

### 1. First SDK Surface

- Choose the first live runner target, e.g. `claude_sdk`.
- Decide whether the initial slice covers candidate generation only, semantic verification only, or both.
- Decide whether the first slice must demonstrate framework portability immediately or only preserve the `AgentRunner` protocol boundary for later.

### 2. Credential Delivery

- Decide how credentials are provided to the runner.
- Decide which environment variables or config files are allowed.
- Decide whether tests may require live credentials, or whether live SDK tests stay opt-in and skipped by default.

Recommended default: live SDK tests should be opt-in only; the normal suite should remain offline and deterministic.

### 3. Sample Assignment

- Select the first real assignment/spec/rubric pair.
- Confirm usage permission, publication permission, and anonymization needs.
- Decide whether the sample can be committed as a fixture, stored privately, or referenced as a local-only path.

### 4. Raw Trace Retention

- Decide what goes into `agent_trace.raw.jsonl` for live SDK runs.
- Decide whether raw traces may include non-public rubric text, prompts, tool responses, or model outputs.
- Decide retention, redaction, and access policy before any live trace is written.

Recommended default: keep audit trace stable and minimal; keep raw trace local/private until the redaction policy is explicit.

### 5. Runner Limits

- Decide `max_turns`.
- Decide cost and timeout ceilings.
- Decide retry behavior for transient SDK/API failures.
- Decide whether partial runner failures are isolated as invalid runs or abort the whole `extract` command.

### 6. Tool Registration

- Map the existing read-only Python tools to the SDK-specific tool/function format.
- Keep the Python tool contract framework-neutral.
- Do not add write/propose tools until the runner batch-emission model is specified.

### 7. Output Contract

- Confirm that live runner artifacts still pass `candidates.schema.json` and `agent_trace.schema.json`.
- Confirm whether the runner may emit `blocked_by_runner_error` and how that status appears in run-local diagnostics.
- Confirm whether `extract --runner <sdk>` uses the same source snapshot generated by `extract` or requires an explicit `--source-manifest`.

## Suggested First Slice

1. Add an SDK runner class behind the existing `AgentRunner` protocol.
2. Keep the normal test suite mocked and deterministic.
3. Add one opt-in smoke test or documented manual command for a local real assignment.
4. Emit candidate artifacts only through the existing normalization and integrity pipeline.
5. Preserve raw trace locally and do not publish it until the retention/redaction policy is finalized.
